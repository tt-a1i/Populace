## Edge Cases

### E1: Residents with no life_goal (None) are handled gracefully in tracking and API
**PASS**

- `engine/goals.py:196`: `track_goals` checks `if goal is None or goal.completed: continue` -- skips None goals.
- `engine/goals.py:167`: `compute_goal_progress` checks `if goal is None or goal.completed: return goal.progress if goal else 0.0`.
- `engine/goals.py:273-274`: `get_resident_goal_view` returns `None` if goal is None.
- `backend/api/residents.py:1056-1057`: API returns `None` when view data is None.
- `frontend/src/components/town/ResidentStoryPanel.tsx:893-894`: Displays fallback text "No life goal assigned" when `lifeGoal` is null.
- Test `test_track_goals_skips_none_goal` and `test_get_resident_goal_view_none` both pass.

### E2: Progress values are clamped between 0 and target (never exceed target or go negative)
**PASS**

- `engine/goals.py:200`: `goal.progress = max(0.0, min(new_progress, goal.target))` -- clamps to `[0, target]`.
- Individual `compute_goal_progress` returns also use `min(..., goal.target)` for social_butterfly (line 172), wealthy (line 174), famous (line 178), family_person (line 180), artist (line 184).
- `_knowledge_progress` returns `[0.0, 1.0]` range (line 133-135).
- `_zone_visit_progress` returns `[0.0, 1.0]` range (line 161).
- Even if `compute_goal_progress` returned a value outside bounds (e.g., negative wallet), the `max(0.0, ...)` in `track_goals` catches it.
- `engine/goals.py:285`: `get_resident_goal_view` clamps percentage: `min(pct, 100.0)`.
- Test `test_progress_clamped_to_target` sets wallet=5000+coins=5000 >> target=1000, confirms `progress <= target`. Passes.

## Additional Findings

No critical, major, or minor findings. The implementation is clean and complete.

**Observations (informational, not blocking):**

1. `engine/goals.py:158-159`: `_zone_visit_progress` returns `1.0` when `all_zones` is empty. This is a reasonable design choice (vacuously true -- no zones to visit means goal is complete), but could be surprising in edge cases where zones haven't loaded yet. Not a bug since this is a defensive fallback.

2. `engine/goals.py:236`: Achievement and bulletin posting are conditional on `hasattr(state, "_achievements_store")` and `hasattr(state, "_bulletin_posts")`. This is intentional duck-typing for test flexibility, but it means completions in a state missing these attributes silently skip achievement/bulletin. The mood boost (lines 230-233) always fires regardless.
