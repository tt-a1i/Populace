# Contract: Romantic Relationships & Marriage System (#91)

## Task
Add a romantic relationship lifecycle to the Populace simulation: confession, dating, marriage, shared economy, deterioration, and divorce. Build on existing `RelationType.love`, `FamilyInfo.partner_id`, and love evolution in social.py.

## Acceptance Criteria

### Functional

- [ ] **F1**: `Resident` has a `relationship_status` field with values: `single`, `dating`, `married`, `divorced` (default `single`)
- [ ] **F2**: When two residents have mutual love relationship with intensity >= 0.7, a confession event is triggered with success probability influenced by mood and personality. On success, both residents transition to `dating` status
- [ ] **F3**: Dating residents gain a `date` schedule phase — they visit cafe/park together during evening hours
- [ ] **F4**: When dating residents have love intensity >= 0.9, a proposal triggers. On success, status transitions to `married`, they share `home_building_id`, and `family.partner_id` is set bidirectionally
- [ ] **F5**: Married residents share economy — income goes to a shared wallet, expenses are split
- [ ] **F6**: When love intensity drops below 0.3 for married residents, quarrel events fire. Below 0.15, divorce triggers: status → `divorced`, partner_id cleared, home assignment reverts
- [ ] **F7**: `GET /api/world/relationships` returns aggregate romance stats (couples_count, marriages, divorces, dating_pairs)
- [ ] **F8**: `GET /api/residents/{id}/romance` returns the resident's relationship_status, partner info (id, name, since_tick), and love_intensity
- [ ] **F9**: Frontend `Resident` type includes `relationship_status` field
- [ ] **F10**: Frontend resident detail panel shows relationship status and partner name when applicable

### Edge Cases

- [ ] **E1**: Confession between residents who are already dating/married with others is blocked
- [ ] **E2**: Divorce properly clears both residents' partner references (no dangling partner_id)
- [ ] **E3**: If a married resident dies, the surviving spouse's status transitions to `single` and partner_id is cleared

### Regression

- [ ] **R1**: Existing love relationship evolution in social.py still works (RelationType transitions)
- [ ] **R2**: Birth logic in lifecycle.py still works for married/love couples
- [ ] **R3**: All pre-existing tests pass (pytest 424+ passed, vitest 184 passed)
